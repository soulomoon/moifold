### Goal
Port PR-review reviewer outcome transitions to the indexed workflow API while preserving the existing moifold compatibility behavior. The covered outcomes are `ReviewerClean`, `ReviewerProblemsAdded`, `ReviewerIncomplete`, and `ReviewerBlocked` as observed through `ObservedReviewerOutcome`, including normal-review clean, verification clean, missing-thread verification fallback, reviewer-found-problems, reviewer-incomplete, and reviewer-blocked transitions from `PrReviewingClean`.

The round must keep event JSON schemas, event `type` fields, golden logs, daemon result shapes, dry-run output, action ordering, classifier evidence, effect plans, replay behavior, permission behavior, and compatibility facades stable.

### Approach
Keep this as a sequential, single-owner change. The roadmap marks `item-009-indexed-pr-review-reviewer-outcomes` as not parallel-safe, and the implementation will touch the same PR-review reviewer outcome observation surface, indexed adapter pattern, Cabal exposure, classifier-backed evidence, and shared indexed parity helpers in `test/Main.hs`. Worker fan-out would create overlapping ownership of transition labels, wrapper types, fixture prefixes, effect-plan assertions, and compatibility comparisons.

Add a moifold-owned indexed adapter for PR-review reviewer outcomes, following the existing `CodexWatcher.Workflow.Moifold.PrReview.Checking.Indexed`, `CodexWatcher.Workflow.Moifold.PrReview.Worker.Indexed`, and `CodexWatcher.Workflow.Moifold.PrReview.Mergeability.Indexed` pattern. Prefer a narrow sibling module such as `src/CodexWatcher/Workflow/Moifold/PrReview/Reviewer/Indexed.hs`, exposed from `moifold.cabal`, rather than widening the checking, worker, or mergeability modules beyond their current intent.

The adapter should wrap existing concrete moifold values and delegate behavior to `MoifoldSpec`: `SomeWatcherState`, `WatcherEvent`, `DaemonObservation`, `ObservedPolicyTick`, `SomeEffect`, `EffectPlan`, and `EventReplayResult`. `agent-workflow-core` continues to own only the generic indexed API; moifold continues to own concrete PR-review lifecycle policy, `WatcherEvent`/`SomeWatcherState`, Aeson event codecs, replay policy, daemon observation projection, runtime effects, app-server/GitHub actions, and dry-run rendering.

Do not route a live daemon call site through the indexed adapter in this round. Do not change `CodexWatcher.Domain.PrReview.Loop`, `CodexWatcher.Domain.PrReview.Watcher` semantics, reviewer output parsing, event codecs, golden fixtures, dry-run text, app-server action rendering, runtime effect rendering, or compatibility module availability except for adding the intentionally narrow indexed adapter module.
