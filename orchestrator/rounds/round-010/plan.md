### Goal
Complete the indexed PR-review mergeability coverage by extending the existing `CodexWatcher.Workflow.Moifold.PrReview.Mergeability.Indexed` slice beyond the current clean path. The round covers mergeability waiting, recheck, fix-required, blocked, stopped, and `PrReviewMergeCompleted` terminal paths while preserving the existing compatibility facade and all externally visible moifold behavior.

The implementation must keep event JSON schemas, event `type` fields, golden logs, daemon result shapes, dry-run output, action ordering, request-id progression, merge pre-commit ordering, effect plans, replay behavior, permission behavior, and compatibility facades stable.

### Approach
Keep this as a sequential, single-owner change. The roadmap marks `item-010-indexed-pr-review-mergeability-complete` as not parallel-safe, and the implementation must update the same mergeability indexed adapter, terminal merge observation path, golden lifecycle prefixes, effect-plan assertions, request-id/action-ordering assertions, and compatibility parity helpers. Worker fan-out would create overlapping ownership of the same transition labels, wrapper types, fixture prefixes, dry-run expectations, and indexed-vs-compatibility comparisons.

Extend the moifold-owned mergeability indexed adapter instead of introducing a new state machine. `CodexWatcher.Workflow.Moifold.PrReview.Mergeability.Indexed` already wraps existing concrete moifold values and delegates to `MoifoldSpec`; keep that pattern and add only the typed point(s) needed for terminal/blocked/stopped merge coverage. `agent-workflow-core` continues to own only the generic indexed API. Moifold continues to own concrete PR-review lifecycle policy, `WatcherEvent`/`SomeWatcherState`, Aeson event codecs, replay policy, daemon observation projection, runtime effects, app-server/GitHub actions, dry-run rendering, and compatibility writes.

Preserve `CodexWatcher.Workflow.Moifold.PrReview.Mergeability.observePrReviewMergeability` as the public mergeability facade for waiting-state observations. Terminal merge completion currently lives in `prReviewObserve` from `PrMerging`; the indexed path should prove parity with that compatibility path without changing daemon routing. Do not route a live daemon call site through the indexed adapter in this round; daemon routing is reserved for item 011.
