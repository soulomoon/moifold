### Approach
Keep the change sequential and single-owner. The selected roadmap item is not parallel-safe: daemon routing, transaction preparation, mergeability indexed projection, and focused daemon tests all touch the same observation path and must be reviewed as one integrated behavior change. Do not write `worker-plan.json`.

Use the existing moifold-owned `CodexWatcher.Workflow.Moifold.PrReview.Mergeability.Indexed` adapter as the indexed boundary. `agent-workflow-core` may only receive a generic transaction helper if needed to avoid duplicating dry-run/execute/failure semantics; it must not learn about `WatcherEvent`, `SomeWatcherState`, `DaemonObservation`, PR-review policy, Aeson codecs, runtime interpreters, app-server/GitHub adapters, or compatibility writes. Moifold continues to own concrete lifecycle policy, event codecs, replay policy, daemon projection, runtime effects, action compilation, and compatibility facades.

The live route should project an indexed plan back into the existing `MoifoldSpec` transaction result shape before returning to daemon callers. Keep `CodexWatcher.Workflow.Moifold.PrReview.Mergeability.observePrReviewMergeability` available and behaviorally unchanged, and keep all existing public compatibility modules available.
